# 答案之书 · 大学生专供版

一本会翻页、会出声的在线答案之书。有想不明白的事，翻开它。

深度墨绿皮革封面、烫金书名、暖白纸张；翻开时纸张翻飞、抽出答案时墨迹浮现，全程都有合成音效。答案条目偏向大学生的日常：外卖、食堂、DDL、熬夜、以及那些你其实心里有数的问题。

- 在线使用：**<https://answers.xingheling.cn>**
- 技术栈：HTML + CSS + 原生 JavaScript，**零依赖、零构建**
- 当前收录 **51 条**答案，持续补充中

## 在线使用

打开 <https://answers.xingheling.cn> 即可，无需安装任何东西。

手机、平板、电脑都能用。窄屏会自动退化成单页模式。

## 本地使用

项目是纯静态的，**不需要编译、不需要装依赖**就能跑起来。有两种方式：

### 方式一：直接双击 `index.html`

最快，但有个限制：浏览器对 `file://` 协议下的 `fetch()` 会以跨域为由拦截，所以页面读不到 `answers.txt`，只能回落到 `js/answers.js` 这份编译产物。

也就是说 —— **你改了 `answers.txt` 之后，得先双击 `build.bat` 重新编译，双击预览才能看到新内容。**

适合只想看看效果、不打算改条目的人。

### 方式二：起一个本地服务器（推荐）

有本地服务器时页面会直接读 `answers.txt` 的最新内容，**改完刷新即可，不用重新编译**。

任选一种：

**Windows 一键启动** —— 双击根目录的 `serve.bat`。它会起服务、自动打开浏览器，按 `Ctrl+C` 停止。（需要装 Node.js）

**有 Node.js** —— 在项目根目录执行：

```bash
npm run serve
```

**有 Python** —— 在项目根目录执行：

```bash
python -m http.server 8765
```

然后浏览器打开 <http://127.0.0.1:8765/>

## 怎么用

| 操作 | 说明 |
|---|---|
| 翻开 | 轻触封面（或按空格 / 回车） |
| 抽答案 | 点「抽取答案」按钮 |
| 再抽一次 | 抽完之后点「再抽一次」，换一条 |
| 复制结果 | 把抽到的答案复制到剪贴板，方便贴给别人 |
| 合上 | 轻触左侧书页（窄屏下点页脚提示），或按 `Esc` |
| 音效开关 | 右上角按钮，可随时静音 |

抽到特定条目时按钮会自动变化：

| 抽到的内容 | 可用按钮 |
|---|---|
| 含「再抽一次也没用」 | 只有「复制结果」 |
| 含「再抽一次」 | 只有「再抽一次」 |
| 其他任意条目 | 「再抽一次」+「复制结果」 |

这是个内部梗：抽到「再抽一次」时，书在鼓励你再抽；抽到「再抽一次也没用」时，它劝你别抽了。

## 添加 / 修改答案条目

所有答案都在根目录的 **`answers.txt`** 里，**一行一条**。

```text
你还有更急的事没做，但你选择翻这本书。
今天不适合做决定，适合吃顿好的。
抽到这条，说明该去食堂了。
```

格式规则很简单：

- 空行会被忽略
- 以 `#` 开头的行会被忽略，可以用作注释
- 行首行尾的空白会被自动去掉

改完之后：

| 你的使用方式 | 要不要重新编译 |
|---|---|
| 本地服务器（`serve.bat` / `npm run serve`） | 不用，刷新即可 |
| 直接双击 `index.html` | 要，双击 `build.bat` |
| 线上站点 | 要，提交后等 GitHub Pages 重新构建 |

`build.bat` 会把 `answers.txt` 编译成 `js/answers.js`。这个文件是自动生成的，**不要手动改** —— 下次编译会被覆盖。

> 为什么要有这个编译步骤？因为双击打开时只能用 `file://` 协议，而它拿不到 `answers.txt`。`js/answers.js` 就是这种情况下唯一的兜底数据源。服务器环境下页面优先读 `txt`，所以永远不会读到脏数据。

答案文字会按长度自动分级字号（四个档位），长句子不会撑破版面。加到 20 多字都没问题。

## 技术说明

### 翻页

核心抽象是一张「叶片」：每次翻页新建一个 DOM 元素贴在右半页，绕中缝（`transform-origin: left center`）旋转 -180°，动画一结束就移除，把状态固化到底层页面。好处是连翻几十次也不会累积 DOM，也不会出现多份 3D 状态互相打架。

推进时序只认 `animationend`，`setTimeout` 仅作为「标签页切到后台时动画事件丢失」的兜底 —— 不用它去猜动画时长，因为猜的必然漂移。

### 抽取节奏

不是匀速翻页，而是指数减速：`t(i) = 45 × e^(i × 0.28)` 毫秒。首次抽取翻 10 页，之后「再抽一次」翻 3 页。

抽选用**洗牌袋**算法：一轮之内不重复抽到同一条，抽完一轮才重新洗牌，并且会避开跨轮的相邻重复。所以不会出现「连抽三次都是同一句」那种像坏掉了一样的体验。

### 音效

全部是 **Web Audio 实时合成**，不加载任何音频文件 —— 噪声源 + 带通/低通滤波 + 包络，模拟纸张摩擦与落页。每次触发都有 ±15% 的随机扰动，所以连翻几十次不会听出机械重复。

首次用户手势（点击封面）时才解锁音频上下文，符合浏览器的自动播放策略。

### 视口自适应

书体尺寸不写死在 CSS 里，而是由 `js/fit.js` 按窗口剩余空间实时计算。

这里有个容易忽略的约束：叶片绕中缝旋转时，转到 90° 附近会离视点最近，被透视放大；书体本身又有 7° 倾角，于是「朝向视点」在屏幕上同时表现为「向上」。两者叠加，**叶片最高点会越过书体上沿**。书体小的时候这块多出来的高度恰好被顶栏留白吃掉、看不出来，一旦把书撑满，它就会被屏幕顶边切平。

所以自适应会为顶部预留一块空间。撑满与「叶片不被切」是一对必须同时满足的约束。

### 无障碍与偏好

- 尊重系统的**减少动态效果**设置（`prefers-reduced-motion`），会缩短甚至取消动画
- 封面、按钮都可用键盘操作，有可见的焦点描边
- 关键信息通过 `aria-live` 播报

## 浏览器要求

需要支持 CSS 3D 变换（`transform-style: preserve-3d`）与 Web Audio API。近几年的 Chrome、Edge、Firefox、Safari 都没问题。

不支持时不会白屏 —— 书还能看，只是翻页没有立体纵深、没有声音。

## 开发者

只有跑测试和本地服务器才需要 Node.js（≥ 18）。站点本身零依赖。

```bash
npm install          # 装测试依赖（playwright-core）

npm run selftest     # 数据层自检：分类规则、洗牌去重、分布均匀性
npm run verify       # 端到端回归：63 项，真实浏览器
npm run probe        # 动效抖动探针：逐帧采样行数
npm test             # = selftest + verify
```

三个脚本都以退出码表示结果，全过为 `0`。

`browser_verify.js` 会自动探测系统里的 Chromium / Chrome / Edge，并在 8765 端口需要时自己起一个静态服务（纯 Node 实现，不需要 Python）。若你的浏览器在特殊位置，用环境变量指定：

```bash
CHROME_PATH=/path/to/chrome npm run verify
PLAYWRIGHT_CORE_PATH=/path/to/playwright-core npm run verify
```

### 回归覆盖面

| 套件 | 项数 | 覆盖内容 |
|---|---|---|
| `selftest.js` | 10 | 特殊条目分类、一轮去重、覆盖全部条目、300 次无相邻重复、分布均匀性 |
| `browser_verify.js` | 63 | 两条数据加载路径、开书抽书状态机、特殊条目按钮规则、复制剪贴板、布局溢出、视口自适应撑满、窄屏单页、翻页时长精确性、连翻 30 次 DOM 零累积、开合动效时序、控制台报错 |
| `reveal_probe.js` | — | 逐帧采样行数与宽度变化，扫描全部真实条目 + 长度 2–30 的合成样本 |

改完 CSS 或 JS 之后建议跑一遍 `npm test`。
